# MEMBERSHIPS – DECISION TREE

Use this for member profiles, bills, subscriptions, payment schemes, wallets, membership payments, and member access.

---

## 1. IDENTIFY MEMBERSHIP ISSUE

IF issue is clear:
→ Go directly to matching section.

IF unclear, ask:
“Is this about a member profile, bill, subscription, payment scheme, wallet/balance, or member access?”

---

## 2. MEMBER CANNOT BE FOUND

IF member cannot be found:

Ask for:
- Name
- Email
- Membership number if available

Then check:
1. Correct member profile
2. Active/inactive status
3. Duplicate profiles
4. Search filters

IF member should exist but cannot be found:
→ Escalate.

---

## 3. BILL LOOKS WRONG

IF bill looks wrong:

Ask:
“What looks incorrect — amount too high, missing payment, or extra charge?”

Then check:
1. Bill details
2. Subscriptions
3. Custom charges
4. Discounts
5. Previous unpaid balance
6. Payment allocation

IF total still does not match:
→ Escalate.

---

## 4. BILL TOO HIGH

IF bill is too high:

Check:
1. Subscriptions applied
2. Custom charges
3. Discounts
4. Previous unpaid balance
5. Payment allocation

IF still incorrect:
→ Escalate.

---

## 5. BILL NOT VISIBLE

IF bill is not visible:

Check:
1. Bill exists
2. Bill is published
3. Correct member profile
4. Member access/status

IF published bill is still not visible:
→ Escalate.

---

## 6. PAYMENT NOT APPLIED TO BILL

IF payment exists but bill still shows unpaid:

Check:
1. Member profile
2. Billing
3. Relevant bill
4. Payment allocation
5. Correct bill/payment link

IF payment exists but cannot be allocated:
→ Escalate.

IF no payment exists:
→ Use payments decision tree.

---

## 7. SUBSCRIPTION ISSUE

IF subscription amount/status is wrong:

Check:
1. Subscription type
2. Amount
3. Start date
4. End date
5. Frequency
6. Discounts
7. Member status

IF asked “What subscription cycle types are available?” respond:

“There are subscription cycle options including Annual, Rolling, Monthly, and Custom.”

Confirm before changing subscription.

Escalate if subscription setup appears correct but bill is wrong.

---

## 8. PAYMENT SCHEME ISSUE

IF payment scheme issue:

Check:
1. Scheme start date
2. Frequency
3. Amount
4. Linked bill
5. Member status
6. Failed payment reason

IF repeated failures or multiple members affected:
→ Escalate.

---

## 9. WALLET / BALANCE ISSUE

IF wallet or balance does not match expectation:

Check:
1. Wallet transactions
2. Bill allocation
3. Previous credits/debits
4. Payments
5. Outstanding balance

IF mismatch remains:
→ Escalate.

---

## 10. INACTIVE MEMBER

IF issue involves inactive member:

Check:
1. Member status
2. Subscription status
3. Payment scheme status
4. Outstanding bills

Confirm before changing member status.

---

## 11. REMOVE / CANCEL SUBSCRIPTION

Before changing:

Confirm:
1. Correct member
2. Correct subscription
3. Effective date
4. Billing impact

Then proceed only if confirmed.

Escalate if change affects billing history or payment schedules.

---

## 12. ESCALATION TRIGGERS

Escalate if:

- Bill total does not match after checks
- Payment exists but cannot be allocated
- Payment scheme repeatedly fails
- Wallet/balance mismatch remains
- Member dispute cannot be resolved
- Billing history appears inconsistent
- Multiple members affected

---

## KEY BEHAVIOUR

Always:
- Check member profile and bill first
- Check allocation before assuming payment is missing
- Confirm before changing subscriptions/status

Never:
- Assume missing payment before checking allocation
- Remove subscriptions without confirmation
- Change member status without confirmation
