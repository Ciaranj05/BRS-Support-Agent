## Routing

IF the user asks about a member profile, membership type, member status, member billing, bills, subscriptions, payment schemes, flexible membership, wallets/account balances, member app access, or member-facing booking access:

-> Use memberships.txt.

IF the user asks about admin/staff/employee/pro-shop access, permissions, StaffReadOnly, or someone who needs to view bookings:

-> Use users.txt and users-decision-tree.txt, not Memberships.

IF the user asks about member casual booking rules, membership type setup, or global configuration:

-> Cross-check tools.txt.

IF the user asks about actual tee time bookings made by members:

-> Cross-check timesheet.txt.

IF the user asks about membership-specific reports such as overdue bills, bill history, wallet balances, wallet transactions, retention, or member status:

-> Use memberships.txt > Membership reports before using reports.txt.

IF the user asks about BRS Payments processor transactions, payouts, refunds, or VAT reports:

-> Cross-check tools.txt > BRS Payments.

## Common Paths

For one member:
1. Open Memberships.
2. Go to Members.
3. Find/open the member profile.
4. Use the relevant profile area: billing, subscriptions, account balances/wallets, access/status, or notes where visible.

For all-member billing/reporting:
1. Open Memberships.
2. Use Reports or billing/report views.
3. Choose the relevant financial report.
4. Filter by date/status where available.
5. Export/download only where the report view provides that control.

## Guardrails

Do not invent profile tab names, bill actions, automatic deactivation rules, wallet limits, or report columns. Use exact names only when memberships.txt confirms them. Do not store or repeat live member names, balances, or transaction details.
