# TEESHEET – DECISION TREE

Use this for tee sheet, booking, player, cancellation, moving booking, and booking visibility issues.

---

## 1. IDENTIFY BOOKING ISSUE

IF user issue is clear:
→ Go directly to matching section.

IF unclear, ask:
“Is this about finding a booking, cancelling, moving a booking, changing players, or tee sheet visibility?”

---

## 2. BOOKING NOT FOUND

IF booking cannot be found:

Ask:
“Can you confirm the booking date and tee time?”

Then check:
1. Correct date
2. Correct course/tee sheet
3. Tee time
4. Player/customer name
5. Whether booking was moved or cancelled

IF still cannot be found:
→ Escalate.

Important:
- Confirm date/time before checking payments.

---

## 3. CANCEL BOOKING

IF user wants to cancel a booking:

Ask for confirmation before cancelling.

Check:
1. Correct booking
2. Customer/player details
3. Payment status
4. Refund requirement

Then guide:
1. Open tee time
2. Open booking
3. Confirm booking
4. Cancel booking

IF payment exists:
→ Use payments/refund decision tree.

Escalate if cancellation fails or refund status is unclear.

---

## 4. MOVE BOOKING

IF user asks how to move, transfer, or reschedule a booking:
→ Answer directly with the Cut and Paste process below.
→ Do not ask whether it is for the same day or a different day.
→ Do not ask whether the booking is for a member or visitor.
→ Do not ask whether it is a single booking or group booking unless the user has already said the standard Cut and Paste process does not work for their case.

The process is the same for member bookings, visitor bookings, same-day moves, and different-day moves.

Before moving, confirm:
1. Original date/time
2. New date/time

Then guide:
1. Click the tee time to open the Booking Details page.
2. Click Cut from inside the Booking Details page.
3. Return to the tee sheet.
4. Go to the new date if the booking is being moved to a different day.
5. Tick the checkbox beside the tee time you want to move the booking to.
6. Click Paste.
7. Check the payment status after moving the booking.

Important:
- Using Cut from inside the booking keeps the payment information attached.
- If the checkbox on the tee sheet is selected first and the booking is cut from there, the payment information will not transfer.
- Never tell users to drag and drop a booking to move it.
- Never tell users to use a Move, Reschedule, or Change Time option for teesheet bookings.
- Never tell users to right-click the booking to move it.
- Never tell users to click a slot to drop the booking.

IF payment total changes:
→ Use payments decision tree.

Escalate if booking cannot be moved or payment status becomes inconsistent.

---

## 5. ADD PLAYER

IF user wants to add a player:

Check:
1. Tee time capacity
2. Booking rules
3. Member/visitor restrictions
4. Price impact

Then guide:
1. Open booking
2. Add player
3. Confirm player type
4. Save
5. Check payment amount if required

---

## 6. REMOVE PLAYER

IF user wants to remove a player:

Confirm before removing.

Then guide:
1. Open booking
2. Remove player
3. Save
4. Check payment status

IF overpayment is created:
→ Use payments/refund decision tree.

---

## 7. BOOKING PAYMENT STATUS

IF user asks about payment colour/status:

Colours:
- Green = Fully paid
- Blue = Part paid
- Red = Unpaid
- Yellow = Overpaid

Then guide:
1. Open booking
2. Go to Payments tab
3. Check payment total
4. Check allocation

IF payment exists but status looks wrong:
→ Use payments decision tree.

---

## 8. TEE TIME / BOOKING NOT VISIBLE ONLINE

IF tee time or booking is not visible online:

Check:
1. Date/time availability
2. Booking rules
3. Member/visitor restrictions
4. Blocked times
5. Competition/society reservations
6. Online booking settings

IF it should be visible but is not:
→ Escalate.

---

## 9. SOCIETY / GROUP BOOKING

IF society/group booking:

Check:
1. Number of players
2. Tee time range
3. Contact details
4. Deposit/payment status
5. Booking notes

IF payment involved:
→ Use payments decision tree.

---

## 10. ESCALATION TRIGGERS

Escalate if:

- Booking cannot be found after date/time checks
- Booking data appears inconsistent
- Booking cannot be moved/cancelled
- Payment status does not match payment record
- Multiple bookings affected
- Tee sheet availability does not match setup

---

## KEY BEHAVIOUR

Always:
- Confirm date/time for missing bookings
- Confirm before cancellation/removal
- Check payment impact after changes
- For moving bookings, give the Cut from inside Booking Details and Paste process directly

Never:
- Jump to payment checks before confirming booking date/time
- Cancel or remove without confirmation
- Ask member/visitor, same-day/different-day, or single/group follow-up questions before giving the standard move booking steps
- Suggest drag and drop, right-click, Move, Reschedule, or Change Time for moving teesheet bookings
