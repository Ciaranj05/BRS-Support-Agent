# USER MANAGEMENT - SUPPORT KNOWLEDGE

Use this knowledge for users, admins, staff access, employee access, login issues, permissions, roles, and deactivating users.

---

## CORE RULE

Always confirm the user and the access level before advising changes.

Do not remove or change user access without confirmation.

Only guide users to role/access options that are documented here. Do not invent account types or payment/setup accounts.

If the latest user message clearly describes an employee, staff member, colleague, worker, receptionist, pro shop user, office user, or someone who needs access to see bookings or the tee sheet, treat it as user-management even if earlier clarification context mentioned members or member profiles.

---

## USER GROUPS

Supported BRS user groups:

- Admin: overall control of the system. Cannot add other Admin users.
- Staff: can complete most day-to-day tasks, but cannot access the Tools menu or Revenue Reports.
- StaffReadOnly: can view but cannot save changes.
- Member: can only log in through the Members Booking pages to view or book tee times.

Treat these as the same StaffReadOnly intent:

- staffreadonly
- staff read only
- staff read-only
- read only staff
- view only staff
- read-only employee
- view-only employee
- new employee can see bookings
- employee can view bookings
- employee can see the tee sheet
- colleague can see bookings but cannot change anything
- receptionist can view the diary or tee sheet only
- pro shop user can view bookings only
- can read or view the tee sheet but cannot change settings
- can see the timesheet but cannot edit or save changes
- can see what bookings are there each day

If the user asks for an account that can view the tee sheet/timesheet/bookings but not change settings, guide them to create an Admin or Staff user and select the StaffReadOnly user group.

If the user says the employee needs to change bookings or complete day-to-day work, use Staff instead of StaffReadOnly.

If unsure which role is needed, ask what the user needs to do in the system.

---

## ADD USER

Before adding a user, confirm:

- Name
- Email address
- Required access level or user group
- Club/location if relevant

Steps:

1. Go to Users >> Add New
2. Click the dropdown beside User Group
3. Choose the correct user group
4. Complete the required fields: User Group, Username, Membership Type, First Name, and Last Name
5. Complete Password and Re-type Password to set the user password
6. Click Create New User

Escalate if user cannot be created or email already exists.

---

## CHANGE USER PERMISSIONS

Before changing permissions, confirm:

- User name/email
- Current user group
- Required user group
- Reason for change

Steps:

1. Go to Users
2. Click Find User
3. Open the user from the list
4. Update the user group or permissions
5. Save
6. Ask the user to log out and back in if needed

Escalate if permissions do not apply after saving.

---

## DEACTIVATE USER

Prefer deactivation over deletion if user history should be retained.

Before deactivating, confirm:

- Correct user
- Reason for deactivation
- Whether access should be removed immediately

Steps:

1. Open user/admin settings
2. Find user
3. Deactivate user
4. Save

Do not deactivate without confirmation.

---

## LOGIN ISSUE

For login issues, check:

- Correct email address
- User account exists
- Account active
- Correct role/access
- Password reset if needed

If multiple users cannot log in, escalate.

---

## USER LIMITS

If user cannot be added due to limit:

1. Check existing active users
2. Deactivate unused users if appropriate
3. Escalate if limit needs review

---

## COMMON CAUSE -> EFFECT

- Incorrect user group may hide features
- StaffReadOnly users can view but cannot save changes
- Inactive account prevents login
- Wrong email prevents password reset
- Browser/cache may affect session after permission changes
- User limit may block new user creation

---

## ESCALATION TRIGGERS

Escalate if:

- User cannot log in after reset/checks
- Permissions do not apply after saving
- Multiple users affected
- User cannot be created
- Account appears duplicated
- Access issue may affect security

---

## RESPONSE STYLE

Preferred format:

1. Confirm the user/access issue
2. Give the exact check
3. Confirm before changing access
4. Escalate if access/security risk exists
