# USER MANAGEMENT – SUPPORT KNOWLEDGE

Use this knowledge for users, admins, staff access, login issues, permissions, roles, and deactivating users.

---

## CORE RULE

Always confirm the user and the access level before advising changes.

Do not remove or change user access without confirmation.

---

## USER ROLES

Common role types:

- Superuser
- Admin
- Staff
- Read Only

Role meaning:

- Superuser: highest access level
- Admin: management access
- Staff: operational access
- Read Only: viewing access only

If unsure which role is needed, ask what the user needs to do in the system.

---

## ADD USER

Before adding a user, confirm:

- Name
- Email address
- Required access level
- Club/location if relevant

Steps:

1. Go to user/admin settings
2. Create new user
3. Enter user details
4. Assign role
5. Save
6. Ask user to check login email or password setup

Escalate if user cannot be created or email already exists.

---

## CHANGE USER PERMISSIONS

Before changing permissions, confirm:

- User name/email
- Current role
- Required role
- Reason for change

Steps:

1. Open user/admin settings
2. Find the user
3. Update role/permissions
4. Save
5. Ask user to log out and back in if needed

Escalate if permissions do not apply after saving.

---

## DEACTIVATE USER

Prefer deactivation over deletion if user history should be retained.

Before deactivating, confirm:

- Correct user
- Reason for deactivation
- Whether access should be removed immediately

Steps:

1. Open user/admin settings
2. Find user
3. Deactivate user
4. Save

Do not deactivate without confirmation.

---

## LOGIN ISSUE

For login issues, check:

- Correct email address
- User account exists
- Account active
- Correct role/access
- Password reset if needed

If multiple users cannot log in, escalate.

---

## USER LIMITS

If user cannot be added due to limit:

1. Check existing active users
2. Deactivate unused users if appropriate
3. Escalate if limit needs review

---

## COMMON CAUSE → EFFECT

- Incorrect role may hide features
- Inactive account prevents login
- Wrong email prevents password reset
- Browser/cache may affect session after permission changes
- User limit may block new user creation

---

## ESCALATION TRIGGERS

Escalate if:

- User cannot log in after reset/checks
- Permissions do not apply after saving
- Multiple users affected
- User cannot be created
- Account appears duplicated
- Access issue may affect security

---

## RESPONSE STYLE

Preferred format:

1. Confirm the user/access issue
2. Give the exact check
3. Confirm before changing access
4. Escalate if access/security risk exists
